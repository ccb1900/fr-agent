## 一、外部审查原文（按原文结构收录）

### 1. 总体评价：r6 达到预定目标

四个值得肯定的决策：Evidence v2 区分"数据库约束"与"数据快照证据"并绑定物理源/模型/Schema；
探针与 Runner 用同一连接配置；TemplateRegression 严格化（读失败不伪装空值、数值不依赖 parseFloat）；
SemanticPreflight 建立清晰的前置裁决边界（没有把所有东西塞进一个 Compiler）。

### 2. r6 仍存在的代码问题

**P1-1 探针的原子性实际上没有完全实现**（`probes/probe_relation_unique.js`）

先写 JSON 再写 TXT；若 JSON 写成功、TXT 写失败，只是把内存 status 改成 failed 并 exit 1，
**磁盘上的 JSON 仍是 passed 证据**。建议：探测/验证全部完成后，JSON 与 TXT 都先写临时文件，
全部成功再原子替换；任一阶段失败，正式证据必须不存在或明确 failed；Runner 仍做自己的完整性校验。

**P1-2 证据的关系完整性有边界漏洞**（`semantic/model/evidence.js`）

`finish()` 用 `table.column` 判证据是否存在。若 relationA 与 relationB 指向同一 `table.key`，
relationA 的证据会让 `out.unique["table.key"]` 为 true，relationB 不会被标 missing。
完整性应以 `acceptedRelations[relationName]` 为主键；`uniqueKeys[table.column]` 只作注入 ModelValidator 的结果。

**P1-3 指纹算法不适合长期安全身份校验**（`semantic/model/evidence.js`）

双种子 FNV 只适合普通变更检测，不具密码学碰撞抵抗；数据库身份/安全证据建议 SHA-256。
另：`canonicalSource()` 直接使用完整 URL，若 JDBC URL 含认证参数，哈希输入会包含它们（虽不输出明文）；
建议 URL 规范化并剔除敏感参数。注意 SHA-256 也不能证明服务器未被伪装，真正的身份可信度取决于连接配置与认证方式。

**P2-1 数据集 Inspector 仍有宽松降级路径**（`template/inspector.js`）

`datasetSnapshot()` 已修，但 `safeNum`/`sheetDims` 仍把失败变 `null`/`0`，`cellText` 把失败变 `''`。
不同接口失败语义不一致——若 Locator/Patch 依赖这些描述，仍可能把"读失败"当"空白"。
建议统一 `{ok:false,error:{operation,message}}`；不必全面重构，但**所有参与 Patch 安全裁决的读取**必须严格失败。

**P2-2 `expectPixelChange` 不能证明修改正确**（`template/regression.js`）

零像素差=失败有价值，但只能证明"图像不完全相同"，不能证明"符合预期"（A→B 被错渲成 C 也会过）。
建议渲染验收拆分：数据断言（关键格必须是预期值）、视觉断言（关键区域必须发生预期变化）、全局 diff（防大面积意外）。
暂不需要 OCR/视觉模型，先把坐标与渲染区域建立映射。

### 3. 验收结论

Evidence v2 / 数据源指纹 / 关系指纹基本达成；精确数值比较实现正确；严格数据集读回主要路径达成；
**探针原子性还需修复、关系完整性有边界漏洞**；视觉回归仍是辅助验证；SemanticPreflight 架构方向正确。

### 4. 下一阶段建议

只开一个非常小的 r6.1：探针真正原子写入（P1）、按 relation 检查完整性（P1）、Evidence 哈希升级及 URL 规范化（P2）、
Inspector 失败语义统一（P2）。完成后**冻结底层架构**。

### 5. 真正应该投入的阶段：Agent 创作闭环

不要造 Agent Runtime，而是把 fr-agent 暴露成一组稳定业务级工具能力（Agent 操作这些接口，
不直接碰 Java 对象/CPT XML/任意 SQL）：

| 工具 | 职责 |
|---|---|
| discover | 发现数据源与 Schema |
| resolve | 业务概念对齐 |
| compile | ReportSpec → CPT |
| patch | 修改已有 CPT |
| validate | 数据与结构验证 |
| preview | 执行和预览 |

期望下一次审查看到的不是又十几个 Validator，而是**第一次完整演示**：
Agent 从一句自然语言需求开始，自己完成一份可执行、数据正确、能预览的帆软报表。

## 三、执行记录

### r7-A-1 探针真原子写入（P1）

- 先算完所有 checks / status，再 `writeTmp` 写 JSON/TXT 两个 `.tmp`，**JSON 最后 move 到正式名**
  （`ATOMIC_MOVE` 不可用时退化为 `REPLACE_EXISTING`）；任一写/移失败 → 尽力把正式 JSON 改写为 `status:"failed"`
  （再失败则删除正式 JSON），并 `exit(1)`。
- **实证**：把 `data/i55_relation_unique_truth.txt.tmp` 预建成目录制造 TXT 写失败 →
  探针 `rc=1`，磁盘 JSON `status:"failed"`；清理后重跑 PASS。

### r7-A-2 关系级完整性（P1）

- `out.acceptedRelations[relationName]` 成为完整性主键；`uniqueKeys[table.column]` 只作 validator 注入结果。
- **测**：同一 `laser_files.file_key` 上挂两个 confirmed N:1 关系，只给 relationA 证据 →
  `unique[key]=true` 但 `missing` 含 `dupKeyRel`（不再互相顶替）。

### r7-A-3 SHA-256 + URL 规范化（P2）

- `hash()` 改为纯 ES5 SHA-256（标准向量 `abc`/空串均对）；`normalizeUrl` 直接**剔除**
  `password/pwd/user/username/userid/sslpwd/truststorepassword` 等参数并折叠悬空分隔符。
- **测**：URL 追加 `;password=SuperSecret123;user=sa` 后 source 指纹不变；换 `databaseName` 指纹变化。
- 诚实边界：SHA-256 只提高碰撞抵抗，不证明服务器未被伪装；真正身份可信度取决于连接配置与认证方式。

### r7-A-4 Inspector 失败语义统一（P2）

- `describe()` → `{ok:true, sheetCount, sheets:[{ok:true,rows,cols}], hasDataset}` 或
  `{ok:false, error:{operation,message}}`；`cellExists/cellText` 同样返回 `{ok,...}`；`safeNum` 删除。
- `Locator.exists`：描述符 `ok:false` 或 sheet 维度 `ok:false` 一律拒；`patch_main` 对 `describe().ok===false` 直接失败。
- **测**：descriptor `ok:false` → 拒；sheet 维度 `ok:false` → 拒；真实 WorkBook 探针 `describe.ok=true` 且每 sheet `ok=true`，后续 dataset 回归全 PASS。

### r7-B Agent 创作闭环（审查 §5）

- 新增工具层 `agent/tools/fr_agent.ps1` + `discover/resolve/validate/preview`.js，契约见 `docs/agent-tools.md`：
  `discover | resolve | compile | patch | validate | preview`，每 verb 输出一行 ASCII JSON，详情写 `logs/agent/*.json`。
  compile 内部走既有 `run.ps1 make_api.js`（REPORT_SPEC/FR_AGENT_RESULT/RESULT_DUMP），patch 走 `patch_main`；
  Agent 不接触 Java/CPT/SQL。
- **演示**（`docs/agent-demo-machine-daily.md`）：独立子代理只凭原句需求 + 工具契约产出
  `examples/report-spec/machine_daily_demo.json`，并显式列出三项不支持的诉求（运行期日期控件、按完成率排序、<80% 高亮）
  与替代方案；主链执行：
  - `compile` success=true、11 阶段全 passed；
  - `validate -ExpectTotals 33531:26531`：合计=明细之和、完成率公式、外部真值对拍全部通过；
  - `preview`：PNG 1587×2245 / 34KB / 非空白。
- **工具层踩坑**：PowerShell 函数里 `$rc = Run-Js ...` 会把 java stdout 一起吞进 `$rc`（导致 verb 无输出）→ 改为直接调用；
  `compile.json` 带 BOM → validate 读取时剥 `\uFEFF`。

## 五、开放项

- 底层架构按审查建议**冻结**：r7 之后不再扩 Validator/编译链。
