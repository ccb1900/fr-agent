## 一、外部审查原文（按原文结构收录）

### 总体评价

上轮 I5.4、I1.1、I6.1 三个方向基本都落到了代码里，且至少几处修的是实际执行链上的缺陷。
项目主要风险已从"功能链条有没有接通"转向"安全性证据是否足够可靠、回归门是否真的能发现错误"。

同时声明：审查者检查了源码、提交记录与仓库验证证据，但**没有在本地 FineReport 环境复跑 12 套测试或真实数据库探针**；
仓库报告的 GREEN/PASS 是项目自报，不是独立复跑结果。

### P1（优先修复）

**P1-1 I5.5 唯一性证据还不能真正保证 JOIN 安全**

现状机制：探针 `COUNT(*)` / `COUNT(DISTINCT file_key)` → 写 `i55_relation_unique_truth.txt` →
`make_api.js` 读文件、匹配两段固定文本 → 标记 `laser_files.file_key` 唯一 → validator 放行 N:1。

三个问题：

- **A 数据快照 ≠ 数据库约束**：今天 538 行唯一，不保证明天插入重复键后仍唯一；旧证据仍被接受，JOIN 可能放大度量。
- **B 证据未绑定数据源/模型版本**：`make_api` 无条件读固定文件，而模型与 Schema 允许 env/ReportSpec 指定其他来源；
  其他数据源只要恰好有同名键，就可能误用旧证据。
- **C 证据文件不是强证据载体**：只做文本匹配，没有证据版本、数据源身份、探测时间、关系指纹。

建议：有 PK/单列 UNIQUE 约束直接采信 Schema；无约束时探针只能是**有时效的数据快照证据**；
至少绑定 `schema source + table + column + model relation + probe timestamp`；数据源不匹配/过期/缺失 → 拒；
长期保证 fan-out 安全最终仍需数据库唯一约束或 SQL 层处理重复键。

**P1-2 复合主键被错误地当成单列唯一键**

`(t.primaryKey || []).forEach(... keys[k.column] = 1)` 把复合主键的每一列都登记为单列唯一。
复合主键只保证组合唯一。`laser_files` 恰为 `(source_id, collection_date, file_id)` 三列复合 PK；
`file_key` 目前靠探针证据通过，所以现有链路未误放行，但**通用规则错误**。
唯一索引同样必须确认是单列索引。建议补四象限测试：单列 PK 认可 / 复合 PK 不认可 / 单列 UNIQUE 认可 / 复合 UNIQUE 不认可。

**P1-3 TemplateRegression 对数据集替换的执行回归没有验证数据正确性**

`if (hasDatasetOp) return { pass: true, ... }`：只要改前改后都能执行就 PASS，不管结果数据是否等于 PatchSpec。
现有集成探针只验证列数与首列类型，未验证完整行数据，也未验证报表执行结果反映预期数据。
建议：写回后重新读回数据集，比较列名/列型/行数/逐格值，再执行报表核对；任一不一致即失败。

### P2

**P2-1 TemplateDiff 数字噪声过滤范围过大**

`isNoise()` 的 `/^[\d,\s.]+$/` 对所有 CDATA 生效（本意是列宽/行高数组）→ 数字型业务单元格（如 123→456）会被整体过滤，
真实数据变化可能漏检。应按 XML 节点上下文判断，只忽略已确认的引擎序列化噪声节点。
`attrTokens()` 也是全局属性多重集，属性在节点间移动但总量不变会漏检。

**P2-2 渲染回归只检查 PNG 是否生成**

`render()` 只判执行是否抛异常、PNG 是否 >1000 字节，没有像素级 diff。
1.69% 的实测是一次性验证记录，不等于每次 Patch 都做像素回归。
建议把像素 diff 纳入流水线：尺寸检查、差异比例、差异区域、允许变化区域。

**P2-3 `replace_cell_value` 固定跳过前两行**

`dataGrid()` 固定 `slice(2)`，隐含"被改格必在前两行"。PatchSpec 允许任意坐标：
改第 5 行会被当成数据区变化而误拒；前两行其他格意外变化又会被整体跳过。
应按具体修改坐标屏蔽预期变更单元格。

### 旧问题（仍未解决）

**P2-4 `javaValue()` 布尔静默 truthiness + PatchSpec 类型校验弱**

`{type:'boolean', value:'false'}`：`"false"` 是 truthy → 变成 `true`。未知类型回退成 String。
建议在 Validator 阶段把列类型、值类型、范围、精度、空值规则确定下来，Patch 层只做转换，不再猜测。

## 三、执行记录

### P1-2 复合唯一键判定修正（先做，独立且最硬）

- **红**：`fast_semantic` 加四象限测（单列 PK / 复合 PK / 单列 UNIQUE / 复合 UNIQUE），复合 PK 当场 FAIL——证实审查主张。
- **改**：`semantic/model/validator.js` `declaredUniqueKeys()` 只在 `primaryKey.length === 1` 时登记该列；
  unique index 仍要求 `columns.length === 1`。复合 PK/UNIQUE 不再把任一单列当唯一。
- **绿**：四象限 4/4 PASS。现有 `laser_files`（三列复合 PK）因此**不再**被误认为 `file_key` 单列唯一，
  只剩数据侧证据一条路——正好被 P1-1 的绑定机制接管。

### P1-1 唯一性证据绑定与时效

- **新件 `semantic/model/evidence.js`（纯函数零 IO/零 java）**：解析探针 JSON、校验
  `schema 源 + probedAt 时效（默认 30 天，可 env `I55_EVIDENCE_MAX_AGE_DAYS` 覆盖）+ unique=true 且 rows===distinct +
  relation 指向 model 中 to-side 恰为该列的关系`；不满足一律不注入，并给 accepted/rejected/stale/mismatched/malformed 分类。
- **探针重写 `probes/probe_relation_unique.js`**：遍历 model 中 confirmed N:1/1:1 的 to-side 键（不再写死 file_key），
  标识符白名单防拼接；输出结构化 `data/i55_relation_unique_truth.json`（schema/probedAt/checks[table,column,rows,distinct,unique,relation]）
  + 人类可读 `.txt`。实测 `laser_files.file_key relation=recordToFile rows=538 distinct=538 unique=true`。
- **`make_api.js`**：删除两段正则文本匹配；改 `ModelEvidence.filter` 注入，未通过项逐条打
  `UNIQUE EVIDENCE rejected/stale/mismatched`；文件缺失打 `UNIQUE EVIDENCE MISSING`。validator 仍零 IO。
- **`model.json` 证据文本更正**：旧 `confirmedBy` 写"file_key 是 laser_files 主键"与事实不符（实为三列复合 PK），
  改为"无 DB 唯一约束，唯一性由探针证据（带源/关系/时效绑定）证明"。
- **live 三连证**：
  1. 正常证据 → `UNIQUE EVIDENCE accepted: laser_files.file_key (recordToFile, 538/538)`，JOIN 日报 `failures=0`；
  2. 移走证据文件 → `exit=2`、`input_load failed`、`UNSUPPORTED_RELATION_KEY`（不再放行 JOIN）；
  3. 把 probedAt 改成 2026-09-01（过期）→ `exit=2`、诊断含 `过期` + `UNSUPPORTED_RELATION_KEY`。
- **诚实边界**：这只是"有时效的数据快照证据"，不是数据库唯一约束；长期 fan-out 安全仍需 DB 约束或 SQL 层去重，
  已写进 evidence.js 头注与 README。

### P1-3 replace_dataset 结果回归

- **新读口**：`template/inspector.js` 加 `datasetSnapshot(wb,name)`（列名/列型/逐格值）。
  API 由 `probes/probe_tabledata_api.js` 反射实证：`getColumnCount/getColumnName(i)/getColumnClass(i)/getRowCount/getValueAt(r,c)`。
- **新裁决**：`TemplateRegression.dataset(expected, actual)` 严格比对列数/列名/列型（含 number⊃integer 等价表）/行数/逐格
  （数字串按数值归一，`7≡"7"`、`1.50≡1.5`）；快照缺失=FAIL。
- **`patch_main.js`**：每个 `replace_dataset` 先比**内存写后快照**，导出后再复制到 reportlets 临时件**再读回比一次**
  （写回文件 ≠ 内存对象），临时件读完即删、不碰基线。
- **集成探针**：`probe_patch_dataset_integration.js` 加同一断言，真 WorkBook PASS（2 列×2 行逐格一致）。
- **live**：`dataset_replace.json` 两条 `dataset regression(in-memory/exported re-read)=PASS`，`rc=0`。

### P2-1 diff 数字噪声按节点 + 属性签名带节点

- **改**：`tokens()` 不再全局 `isNoise`；数字/长数字噪声只在 `RowHeight/ColumnWidth/Height/Width` 节点内忽略，
  UUID 仍全局（引擎生成 ID）。`attrTokens()` 改为 `tag/attr=value`，属性跨节点移动总量不变也能识别。
- **红→绿测**：`123→456` 的 `<O>` 单元格变化 → clean=false（旧实现会漏检）；`RowHeight` 数字数组变化 → 仍 clean；
  `name=x` 从 `<O>` 移到 `<P>` → clean=false。

### P2-2 渲染像素 diff 进流水线

- **改**：`patch_main.pixelStats()`（`javax.imageio`）比对前后 PNG：尺寸必须一致，统计差异像素数/比例/包围盒；
  `TemplateRegression.render(before, after, stats, {maxRatio:0.05})` 在 stats 缺失、尺寸变化、比例超阈值时一律 FAIL。
- **live**：rename 例 `render regression=PASS(像素差异 1.69% ≤ 5%（bbox=147,55 - 435,1951）)`。
- **踩坑留痕**：改写时 `new (J('...')).export(...)` 少了一组括号，被解析成"对 Class 对象调 export"；
  真实 live 立即暴露 `TypeError: ...export is not a function`，修正后 PASS（印证"渲染门必须真跑"）。

### P2-3 执行回归按修改坐标屏蔽

- **改**：`execGrid` 返回二维 rows；`execution(before, after, {changedCells})` 只屏蔽 PatchSpec 点名的坐标，
  不再 `slice(2)` 固定跳前两行。
- **合并格**：真实标题是合并单元格，改 (0,0) 后结果栅格 r0c1 同变 → 屏蔽规则扩为"同坐标，或同行的
  `旧值→新值` 重复格"；别的格被改成同新值仍 FAIL（负测断言）。
- **live**：rename 例 execution PASS（13 行），此前旧实现是"整两行跳过"。

### P2-4 PatchSpec 类型严格化

- **改**：`TemplateOps.DS_TYPES` 一处真相（与 patch.js DS_JTYPE 同集合）；`TemplateValidator` 校验列名非空/不重复、
  列型 ∈ 词表、逐格值型（integer/long 必须整数、boolean 必须真布尔、date/datetime 必须合法格式）；
  `patch.js` `javaValue()` 未知列型直接抛、boolean 非布尔直接抛（`"false"` 不再翻成 true），date/datetime 做 `T→空格` 归一。
- **红→绿测**：未知列型、列名重复、boolean 收 `"false"`、integer 收 `"7"`、日期 13 月 → 全拒；合法三列负误报。

## 五、开放项

- 数据侧唯一性证据仍只是**有时效快照**：TTL 默认 30 天，过期即拒 JOIN；长期保证需 DB 单列唯一约束（首选）
  或在 SQL 层显式去重（未做，避免静默改数）。
- 像素 diff 目前是全局比例阈值 5% + 尺寸一致，未做"允许变化区域"掩码；标题/排版类改动可能因版式位移逼近阈值，
  下一步可按 PatchSpec 坐标映射到像素区域做局部豁免。
- `replace_cell_value` 在合并格场景按"同行同旧→同新"屏蔽；若未来支持跨行合并（纵向合并），需扩展为二维区域。
- I6 白名单仍两类 op；类型系统已严格化，但 style/column-width 等 op 的 R0 探针仍是前提。
