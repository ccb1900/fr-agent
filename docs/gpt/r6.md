### 3. 本轮新发现的问题

**P1-1 唯一性证据没有绑定真实数据库身份**

`evidence.js` 只绑了 `schema/probedAt/table/column/relation`；`make_api` 的 `evSource` 实际取
`rs.dataset.schema || modelObj.source || 'atom_live_demo'`，是**逻辑 Schema 名称**；而 SQL 连接可通过
`SQL_URL/SQL_USER/SQL_DRIVER` 切换。逻辑名相同 ≠ 物理数据源相同 → 换库后旧证据仍可能被接受。
建议增加 `sourceFingerprint / modelFingerprint / schemaFingerprint`（指纹只含连接的非敏感部分，不放密码）；
且探针与 Runner 必须使用同一套连接配置。

**P1-2 唯一性探针可能部分失败仍退出 0**

`catch (e) { out.push('PROBE FAIL: ' + e); }` 之后仍 `System.exit(0)`；部分 checks 落盘，Runner 只验证已有 checks，
不校验"每条待探测关系是否都有对应记录" → 探针整体失败仍可能被消费。
建议：全局 `status:"failed"` + `exit(1)`；Runner 只接受 `status:"passed"`；每条待验证关系有且只有一条 check；
不允许部分成功当完整证据。

**P1-3 证据没有绑定完整关系定义**

`relationMatches()` 只比 `name + to.table + to.column`，不比 `from.table/from.column/cardinality/source`。
关系定义任意变化后旧证据应失效。建议完整关系指纹。

**P2-1 datasetSnapshot 反射失败会降级**

`getColumnClass` 失败 → `'text'`；`getValueAt` 失败 → `null`。读取失败与读到空值是两种状态；
若 PatchSpec 恰好也是空值就可能误通过。建议返回 `{ok:false,error,...}` 明确失败。

**P2-2 数字归一化可能损失精度**

`normCell()` 用 `parseFloat`：`9007199254740992` 与 `9007199254740993` 无法区分；Decimal 高精度也不安全。
建议整数按字符串精确比较、Decimal 按十进制规范化，不以 IEEE-754 作为数据库数值比较标准。

**P2-3 像素回归 5% 全局阈值粗糙**

比例不等于视觉正确性：关键指标 79.12→97.12 面积很小仍可能通过；边缘抗锯齿大面积轻微变化可能误拒。
建议增加关键单元格内容断言、关键区域差异、非关键区域允许变化，全局比例只作辅助。

### 4. 架构提醒

`make_api.js` 的 SQL 生成前已串了 ReportSpec Validator / ModelValidator / ModelEvidence / Schema Snapshot /
SQLBuilder / SpecCompiler，建议抽出很薄的 `semantic/preflight.js`：只做
"load model → schema → evidence → validate → 返回 accepted context 或 errors"，**不接管** SQLBuilder、
ReportSpec Validator 或实际数据库连接，让 make_api 更干净。

## 三、执行记录

### r6-A Evidence 完整性（P1×3）

- **evidence v2 契约**：`{evidenceVersion:"2", status, schema, sourceFingerprint, modelFingerprint, schemaFingerprint, probedAt, checks[{table,column,rows,distinct,unique,relation,relationFingerprint}], error}`
  - `sourceFingerprint` = hash(driver + url)，**不含 user/password**；换 `SQL_URL` 即变。
  - `modelFingerprint` = hash(modelVersion/domain/source + 全部关系的规范形)。
  - `schemaFingerprint` = hash(表/列/主键/索引的规范投影)。
  - `relationFingerprint` = hash(name/source/cardinality/from.table/from.column/to.table/to.column)。
- **探针原子性**：探针与 Runner 共用同一套 `SQL_DRIVER/SQL_URL/SQL_USER + dbpass`（不再硬编码）；
  目标关系改为 `ModelEvidence.requiredRelations(model)`（confirmed N:1/1:1）；任一查询失败或任一 check 不唯一 →
  `status:"failed"`、`exit(1)`，Runner 只消费 `status:"passed"`。
- **完整性**：`filter()` 无论在哪一步失败都会补齐 `missing`（每条待验证关系必须有且只有一条被接受的证据）；
  同一关系多条 check → `duplicates` 且不注入。
- **live 三连证**：
  1. 正常：`EVIDENCE_ACCEPTED … PREFLIGHT OK（证据 accepted=1，missing=0）` + JOIN 日报 11 阶段全 passed；
  2. 把 `SQL_URL` 换成 `other_db`：`exit=2`，诊断含"物理数据源指纹不匹配（证据=cf83… 当前=4a6c…）"+ `EVIDENCE_MISSING` + `UNSUPPORTED_RELATION_KEY`；
  3. 探针用坏连接跑：`rc=1`、证据文件 `status:"failed"`（不可被消费）；恢复后重新探针 PASS。

### r6-B Template 数据可信度（P2×2）

- **严格读回**：`datasetSnapshot` 改为 `{ok:true, columns, rows}` / `{ok:false, error, …}`；
  `getTableData/getColumnCount/getRowCount/getColumnName/getColumnClass/getValueAt` 任一失败都返回错误，
  不再降级成 `'text'`/`null`。`regression.dataset` 要求 `actual.ok === true`。
- **精确数值**：`normCell` 不再 `parseFloat`，改为十进制字符串规范化（去前导零/尾零、保号、`-0→0`），
  大整数按字符串比较（`…992` 与 `…993` 可区分），Decimal 精度不丢。
- **PatchSpec 精确表达**：数值列允许字符串形态（`long/decimal` 大数不经 IEEE-754），`javaValue` 走 Java String 重载；
  `validator` 对字符串做数字语法校验，非法仍拒。
- **测**：快照 `ok:false` → FAIL 且 reason 含 `getValueAt`；2^53 相邻值 FAIL/相同值 PASS；`1.50≡1.5` 且
  `1.5000000000000001≠1.5`；`007≡7`；数值列精确字符串零误报、`"abc"` 仍拒。

### r6-C 视觉回归加强（P2）

- **关键单元格内容断言**：`execution(..., {keyCells:[{r,c,expect}]})` —— 修改后执行结果在指定坐标必须等于新值，
  防"对象改了但出表仍是旧值"（同时保留坐标屏蔽与合并格规则）。
- **渲染必须真的变化**：`render(..., {expectPixelChange:true})` —— 有 op 时 `diffPixels>0`，否则 FAIL（零像素差=没落到画面）。
- 像素比例仍保留 5% 上限 + 尺寸一致 + bbox；比例只作辅助，数据正确性由 keyCells + dataset 快照 + 执行栅格三线保证。
- **live**：rename 例 execution/render/diff 全 PASS；dataset 例双向 dataset PASS + 渲染有变化。

### r6-D SemanticPreflight（P3）

- 新件 `semantic/preflight.js`（纯函数、零 Java）：输入 `{reportSpec, model, schema, evidenceRaw, connection, nowMs, maxAgeDays}`，
  输出 `{ok, diagnostics[{code,path,message,severity}], context:{model,schema,uniqueKeyEvidence,evidence,fingerprints}}`。
  只做指纹+回溯+证据完整性；**不接管** SpecValidator / SqlBuilder / 数据库连接。
- `make_api.js` SQL 分支改为：连接身份解析一次（drvC/urlC/usrC）→ preflight → 编译；`SPEC.connections` 复用同一份连接配置。
- **测**：合格→ok+注入证据；缺 schema→error；无证据→`EVIDENCE_MISSING` error；换库→error；诊断形状四段齐全。
